# Bug 0001：DDR3 初始化失败与复位时序

- 日期：2026-11-25
- 状态：已修复
- 涉及：板载 DDR3、高云 DDR3 Memory Interface IP、复位时序

## 一、现象

自建的最小 DDR3 验证工程（写 16 拍 128 位再读回比对，三个 LED 分别指示 PLL 锁定、DDR3 初始化完成、读写正确）出现三种异常，前后共三态：

| 阶段 | 现象 |
| --- | --- |
| 初版 | LED0（PLL）亮，LED1（初始化完成）始终不亮，读写测试不启动 |
| 第二次 | LED1 能亮，但上电后要等约 60 秒 |
| 第三次 | 上电 6 秒内正常，但按按键复位后，LED1 又要等近 60 秒才恢复 |

第三种状态最容易被误判成硬件故障，实际是设计问题。

## 二、环境

| 项 | 值 |
| --- | --- |
| 板卡 | 小梅哥 ACG720-138K（二手购入） |
| 器件 | GW5AST-LV138PG484AC1/I0，Device Version C |
| DDR3 | 单颗 16 位，256 MB，用户接口 128 位，1:4 时钟比 |
| 工具 | Gowin EDA V1.9.12.04 |
| 例程来源 | 小梅哥资料包第 38 章（串口传图 + DDR3 帧缓存） |

## 三、排查过程

### 3.1 先排除例程本身

资料包里有三个 DDR 相关章节，逐一核对工程文件里的器件型号：

| 章 | 工程里的器件 | 结论 |
| --- | --- | --- |
| 第 36 章 | `GW5AST-LV138FPG676AES`（FPGA676 封装） | 不能用，引脚与封装都不对 |
| 第 37 章 | `GW5AT-LV138PG484AC1/I0` | 无 `.cst` 约束文件，是纯仿真例程 |
| 第 38 章 | `GW5AT-LV138PG484AC1/I0` | 可用 |

第 36 章还有个更根本的问题：它的 `DRAM_NUM = 2`，即 IP 按 **32 位 DQ** 生成，而本板是 16 位。这个参数固化在 IP 内部，改引脚也没用。

所以最终以第 38 章的 IP 和约束文件为基础，只新写顶层。

逐条核对第 38 章 `.cst` 与厂家通用管脚分配表：CK、CKE、CS、RESET、DM、DQS、BA、ADDR、DQ 全部一致，确认该例程确实适配本板 484 封装。

### 3.2 定位到 IP 版本

第一次跑通时初始化要 60 秒。查布线报告发现两处：

```
<Device Version>: B
<Timing Constraints File>: ---
```

工程器件选的是 **B 版**，而板上芯片是 **C 版**；同时缺少时序约束文件。

补 `.sdc` 并把器件改成 C 版后，时间从 60 秒降到几十秒，但仍不正常。

再看 IP 源文件的头部：

```
//Written by GowinSynthesis
//Tool Version "V1.9.10.03 (64-bit)"
//Wed Dec 11 17:25:29 2024
`pragma protect begin_protected
`pragma protect data_method="aes128-cfb"
```

**这是加密 IP，内容在生成那一刻就固化了**，并且是用 Gowin V1.9.10.03 按 B 版器件生成的。用 B 版的加密块跑 C 版芯片，PHY 校准会跑到边缘状态。

用 IP Core Generator 按本机器件（C 版）重新生成后，初始化降到 **6 秒内**。

### 3.3 定位到复位时序

版本问题解决后，按按键复位仍要等近 60 秒。对比上电与复位的差别：

- 上电：`reset_n` 从 0 时刻就是高，IP 从未被复位，只是等时钟；PLL 锁定后自然开始跑
- 按键复位：`reset_n` 拉低 → PLL 与 IP 同时复位；松手后 `reset_n` 立刻拉高，**但此时 200MHz 还没恢复**，IP 在无时钟状态下启动初始化

为「让 IP 等 PLL 锁定」，曾把 `rst_n` 直接接到 `pll_lock`，结果初始化**完全起不来**——复位释放与时钟起始是同一瞬间，IP 内部同步复位踩在时钟刚起步的采样窗口上。

## 四、根因

两个独立问题叠加：

### 根因 1：加密 IP 与器件版本不匹配

加密 IP 内部包含 PHY 校准算法和器件相关原语，按生成时的器件版本固化。跨版本使用不会报错，但校准变慢甚至失败。

### 根因 2：IP 复位必须在时钟稳定之后释放

| 复位接法 | 释放时刻 | 结果 |
| --- | --- | --- |
| 接按键 `reset_n` | 松手即释放，早于 PLL 锁定 | IP 无时钟启动，等超时后重试，约 60 秒 |
| 接 `pll_lock` | 与时钟起始同拍 | 采样踩在窗口上，初始化起不来 |
| 延迟释放（锁定后等 256 拍） | 时钟已稳定运行 | 正常，6 秒内完成 |

厂商例程用按键复位看似能用，是因为按键不按时它一直为高，IP 从头到尾没被复位过，**恰好绕开了**这个约束——不是它做对了，是没触发。

## 五、修法

```verilog
// PLL 锁定后，用 200MHz 再数 256 拍，等时钟稳定了才释放 IP 复位
reg  [7:0] rst_cnt;
always @(posedge clk200m or negedge pll_lock) begin
    if (!pll_lock)              rst_cnt <= 8'd0;
    else if (rst_cnt != 8'hFF)  rst_cnt <= rst_cnt + 8'd1;
end
wire ddr_rst_n = (rst_cnt == 8'hFF);

DDR3_Memory_Interface_Top u_ddr3 (
    .rst_n (ddr_rst_n),
    ...
);
```

配套的状态机复位条件也要跟着改。原写法只在 IP 输出 `ddr_rst` 时复位状态机，但按键复位时该信号不一定脉冲，导致状态机停在 `S_DONE` 不重测。改为：

```verilog
if (ddr_rst || !init_calib_complete) begin
    st <= S_IDLE; idx <= 8'd0; fail <= 1'b0;
end
```

## 六、验证结果

| 项 | 结果 |
| --- | --- |
| 上电 | LED0 → LED1 → LED2，6 秒内依次亮起 |
| 按键复位 | 三个灯依次熄灭再依次亮起，恢复时间与上电一致 |
| DDR3 读写 | 16 拍（每拍 128 位）写入后逐拍读回，数据全部一致 |

## 七、可迁移的经验

1. **加密 IP 必须按当前工程器件重新生成。** 拿到厂商例程先看 IP 源文件头的工具版本和日期，与本机环境不一致就重新生成，不要直接编译。

2. **复位释放是硬约束，不是风格选择。** 有依赖关系的模块之间，复位要从上游往下游依次释放：时钟先稳，从设备后放。释放太早会空转等待，与时钟起始同拍会采样违例。

3. **「例程能跑」不等于「例程写对了」。** 例程可能只是没触发某个边界条件。要问「它为什么在这个场景下没问题」，而不是照抄。

4. **LED 分级指示能大幅缩短定位时间。** 本工程把 PLL 锁定、初始化完成、读写正确分成三个灯，才能一眼区分「时钟问题」「IP 问题」「数据问题」。
